## BUG-018 — Runner facing (primary fix)

### User report

Runner enemy may face the wrong way during movement — possibly an old bug reintroduced in recent commits when graphics QA adjusted rotation.

### Code audit (2026-05-18)

**Spawn mapping** (`RunScene.ts`):

```ts
const enemyAssetKeys = {
  runner: "kenney-enemy-runner",  // Kenney PNG — THIS IS THE BUG SCOPE
  bat: "enemy-runner",            // Project SVG + tint — NOT the same asset
  // ...
};
```

**Rotation** (`RunScene.ts` ~167–180, ~1782–1790):

- `spriteFacingOffset["kenney-enemy-runner"]` is currently **`Math.PI / 2`** (DEC-021 / BUG-017).
- On spawn: `facingOffset: spriteFacingOffset[assetKey] ?? 0` stored on enemy.
- Each frame: `moveEnemies()` → `rotateSpriteToward(body, angle, enemy.facingOffset, delta)` toward next waypoint in `path[]`.

**Path waypoints** (game coords 390×694):

```ts
const path = [
  (195, 28),   // spawn area — move toward ↓
  (195, 108),  // vertical leg
  (96, 200),   // diagonal ↙
  (286, 300),  // diagonal ↘
  (195, 448),  // vertical ↓ to fort
];
```

**Git history (important):**

| Commit | `kenney-enemy-runner` offset |
|--------|------------------------------|
| `b1d2bb4` — “Add run graphics polish, rotation fixes…” | **`0`** |
| Current (post DEC-021 / BUG-017) | **`+π/2`** |

`docs/handoffs/2026-05-18-graphics-qa.md` still says “runner `0`” in notes — **stale**; code/docs now say `+π/2` with art “faces up”. User seeing wrong facing suggests either:

1. **`+π/2` is wrong** for the Kenney PNG (art may face **right** like grunt → use `0`), or  
2. **Only some path legs** look wrong (acceptable tuning), or  
3. User confuses **`runner`** with **`bat`** (SVG `enemy-runner` — same offset row but different silhouette).

### Fix procedure (minimal)

1. Play **wave 2** at 1.5×; watch **orange/fast runners** (Kenney PNG, not purple bat).
2. On **vertical** segment (195,28)→(195,108): sprite “nose” should point **down**.
3. On **horizontal-ish** segments: sprite should point along travel.
4. Change **only** `spriteFacingOffset["kenney-enemy-runner"]` — toggle `0` vs `Math.PI / 2` (and only if needed, re-check `enemy-runner` for bat on wave 6).
5. Update `docs/GRAPHICS.md` rotation table to match.
6. If DEC-021 was wrong, add **DEC-026** or amend DEC-021 with reason + date.

**Do not** change tank/shield/grunt offsets unless the same playtest shows they regressed.

- [ ] Bat (wave 6+, tinted SVG) still faces correctly — separate key `enemy-runner`.
