## Confirmed issue inventory (starter list)

Use this as the minimum audit checklist. **Verify in browser + code** — several items are “missing logic” not “missing UI.”

### P0 — Meta progression broken or misleading

| ID | Issue | Evidence (code / UX) | Likely fix area |
|----|--------|----------------------|-----------------|
| **AUD-001** | **No gems unless fort dies** | `claimRunRewards()` only from `claimEndOfRunRewards()` on `fortHp <= 0` (`RunScene.ts` ~1393–1395). Leaving run early earns **0** gems. | Award partial gems on wave clear and/or abandon confirm |
| **AUD-002** | **`bestWave` never updates mid-progress** | Same as AUD-001 — `bestWave` only in `claimRunRewards`. Clearing wave 5 then tapping **Home** leaves `bestWave` at 1 → heroes/maps stay locked. | Persist `highestWaveThisRun` / update `bestWave` on each wave clear |
| **AUD-003** | **“Permanent upgrades” feel broken** | `buyPermanentUpgrade` **is implemented** (`useGameStore.ts` ~146–168) and wired in `PermanentUpgradesScreen` (`App.tsx` ~348–382). With **0 gems**, rows use `.locked` styling — reads as non-functional. | Depends on AUD-001 + UX (enabled state, toast on broke) |
| **AUD-004** | **Home screen progress tracing thin** | Home shows `Best` / `Gems` / `Run W{n}` (`App.tsx` ~175–178). `Run` uses Zustand `run` snapshot from last `setRunSnapshot` — **stale** after leaving Play; no “last run rewards”, no wave-reached-this-session. | Home metrics + post-run summary screen |
| **AUD-005** | **Wave unlock copy vs logic mismatch** | Heroes/maps use `progress.bestWave >= getUnlockWave(unlock)` (`App.tsx` ~257–291). Unlock strings say “Clear wave 5” but player must **finish a run** that dies with `wave >= 5`. Never awards on clear-alone. | Align copy OR award `bestWave` on wave clear (see AUD-002) |
